# SheetSage2 WebUI · 使用说明

把一首歌的录音丢进去，自动扒出**主旋律 / 器乐 / 和弦 / 节拍 / 调性 / 段落**，
导出成 **Synthesizer V 工程（SVP 153）/ MIDI**；在**钢琴卷帘**上改音符、填歌词，离线试听。

> 扒谱质量、和弦准确度、SVP 在各版本 SynthV 里的兼容性都还在持续验证，
> 欢迎按「哪首歌、什么现象、生成的产物」的格式反馈。

---

## 0. 先看这里：你打算怎么用

| 方式 | 适合谁 | 怎么开始 |
| --- | --- | --- |
| **整合包**（网盘分发，链接见 B站视频简介与置顶评论） | 只想用，不想碰命令行 | 解压 → 双击 **`start.bat`**。全量包**不需要装任何东西**，断网也能跑 |
| **源码**（本仓库） | 想看代码 / 想改 | 见下方「从源码跑起来」 |

### 从源码跑起来

需要 **Windows x64 + Python 3.12**（Linux / macOS 未验证）。还需要 `ffmpeg` 在 `PATH` 上。

```bat
:: 1) 建虚拟环境并装依赖
uv venv --python 3.12 .venv
uv pip install --python .venv\Scripts\python.exe -r requirements-base.txt

::    想要 GPU 加速，再把 torch 换成 CUDA 版（版本必须与 torchaudio 完全一致）
uv pip install --python .venv\Scripts\python.exe ^
    torch==2.10.0 torchaudio==2.10.0 --index-url https://download.pytorch.org/whl/cu130

:: 2) 下载模型权重（约 2.6 GB，仓库里不带权重，原因见 THIRD_PARTY_NOTICES.md）
.venv\Scripts\python.exe -m pip install -U huggingface_hub
.venv\Scripts\huggingface-cli.exe login
.venv\Scripts\python.exe tools\download_models.py

:: 3) 启动
start.bat
```

> **模型权重是 gated 的**：先登录 Hugging Face，在
> [m-a-p/SheetSage2](https://huggingface.co/m-a-p/SheetSage2) 和
> [m-a-p/MERT-v2-FullSong](https://huggingface.co/m-a-p/MERT-v2-FullSong)
> 两个页面各点一次同意，再执行 `huggingface-cli login`。
> 国内网络可先 `set HF_ENDPOINT=https://hf-mirror.com`。

## 1. 硬件要求

| 项 | 要求 |
| --- | --- |
| 系统 | Windows 10 / 11，64 位 |
| 显卡 | **非必需**。有 NVIDIA 显卡（显存 ≥ 4 GB）最快；没有也能跑，走 CPU |
| 速度参考 | RTX 3080 12G：5 分钟的 FullSong 约 **1 分钟**；纯 CPU 大约 **15–40 分钟**（看核心数） |
| 磁盘 | 源码方式约 3.5 GB（含权重）；整合包解压后约 6 GB |
| 网络 | 只有装环境和下权重时需要，之后可完全离线 |

**没有显卡怎么办？** 什么都不用改。程序启动时会自己判定：
能上 GPU 就上 GPU，上不了（没卡 / 驱动太老 / 显存被占满）就自动退回 CPU，
并把结论写进页面顶部的提示条和底部状态栏。

想**强制**用 CPU（比如显卡同时要打游戏）：用记事本打开 `settings.json`，
把 `"default_device": "auto"` 改成 `"cpu"`，保存后重开 `start.bat`。

### 关于 torch 版本

程序里**没有任何 torch 版本断言**，换版本不会报"不支持"。三个已知约束：

* `transformers` 声明 `torch>=2.2`；
* 便携运行时是 **CPython 3.12**，而 torch 从 **2.2.0** 起才提供 cp312 的 Windows wheel；
* numpy 钉在 2.5，而 **torch < 2.3 与 numpy 2.x 有已知的 C-API 不兼容**。

所以真要用老版本，建议**不要低于 2.6**。实测跑通的是 `torch 2.6.0+cpu` 与
`torch 2.10.0`（cu130，GPU 与 CPU 都跑过）；2.2–2.5 只是按声明推算、**没有实测**。

⚠️ `cu130` 源里只有 torch ≥ 2.9。要装更老的 CUDA 版得同时换源，
例如 `--index-url https://download.pytorch.org/whl/cu124`。

## 2. 跑起来

1. 双击 **`start.bat`**
2. 会弹出一个黑色命令行窗口（**别关它**，关了服务就停了），浏览器自动打开
   `http://127.0.0.1:8777/`
   窗口里会先把环境摊开给你看：解释器路径、ffmpeg 路径、**以及这次会用 GPU 还是 CPU** ——
   出问题时就照这几行一起发出来。
3. 环境有问题时页面顶部会自动弹红条（写明是哪一项、怎么修）；能跑就不会拦你。
   底部状态栏左边常显**这次用的是 GPU 还是 CPU**、显存占用多少。
4. 按页面上的 ①→⑤ 走：

| 步骤 | 干什么 |
| --- | --- |
| ① 拖入音频 | 拖 `.wav` / `.mp3` / `.flac` 进去（单曲最大 300 MB）。**计算精度**、**只分析前 N 秒**、**开始扒谱 / 停止** 也都在这一张卡上 |
| ② 进度 | 等它跑完；旁边的「分析概览」会给出 BPM、调性、段落、**和弦进行**（可下载 .txt / .csv） |
| **③ 钢琴卷帘** | **改谱就在这里**：左边是琴键、右边是音符，可以直接拖、拉、加、删，还能**在音符上填歌词**；下面有**离线钢琴试听**（播放时音符高亮）。顶部「**导出内容**」有三个勾选 |
| ⑤ 导出 | **导出 SVP**（给 Synthesizer V Studio）、**导出 MIDI** |

> **③ 怎么改谱（钢琴卷帘）**
>
> **先选曲目。** 卷帘上方「**曲目**」那一排是切换轨道的：
> 一次**只编辑一条轨**（跟导出的 SVP 一样，一轨一条单声部线），
> 当前轨是亮的，其他轨淡显做对照（不想看就取消「显示其他轨」）。
>
> | 想干什么 | 怎么做 |
> | --- | --- |
> | 加一个音 | **双击**空白处 |
> | 改音高 / 改时间 | 直接**拖**音符（上下改音高，左右改时间，可以一起动） |
> | 改长短 | 拖音符**右边缘** |
> | 删掉 | 选中后按 `Delete`，或**右键**点它 |
> | 框选一堆 | **Shift + 拖动**框选 |
> | **全选当前曲目** | **`Ctrl+A`** |
> | **吸附到网格** | **`Ctrl+G`**（有选中就只吸附选中的，没选中就整条当前轨） |
> | 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Shift+Z` |
> | 挪一点点 | 方向键；按住 `Shift` 是整八度 |
> | **放大 / 缩小时间轴** | **`Ctrl+滚轮`**（以鼠标位置为中心缩放）或左上角的 `＋` / `－` / `适宽` |
> | **定位 / 试听某一段** | **按住标尺上那个粉色小三角左右拖**（松手才跳，拖的时候不卡）；或者**点卷帘空白处**直接跳过去 |
> | 试听一个音 | 点左边的琴键 |
>
> **音符不会重叠。** 同一条轨里把音符往前拖、压到前一个音符身上时，
> 它会**停在前一个音符的结束点**（后面的音符依次往后让）。
> 这是故意的：Synthesizer V 一条轨只能有一个音同时响，导出一条完整的旋律线才好用。
> 要"两个音同时响"就分到两条轨上。
>
> **改完不用特意保存**：**停止改动 0.3 秒后会自动保存并刷新预览**（拖动、拉伸、增删、
> 填歌词都算改动）。想立刻生效就点「保存并重新生成」。
>
> **网格**在左上角选，9 档：四分音符、8 分、**16 分（默认）**、16 分三连音、
> 32 分、32 分三连音、64 分、64 分三连音、128 分。
> 程序按**音乐位置**画网格，所以变速的歌网格也不会跑偏。
>
> 看细节请用 **`Ctrl+滚轮`** 横向放大 —— 在卷帘上它**不会**缩放整个网页，
> 只缩放时间轴，而且以鼠标指的位置为中心。普通滚轮仍是正常翻页。
>
> 改完记得点 **「保存并重新生成」**，导出才会用到你的修改。
> 点「导出」时如果还有没保存的改动，程序会先自动保存一次。

> **③ 怎么填歌词**（三种填法，按需选）
>
> **① 一个个填**：**点一个音符**，「歌词」框亮起来，打字（中文可用输入法）；
> 按 **回车**自动跳到**下一个音符**，一路填下去。
>
> **② 整段贴**（推荐，快）：先点上方「**曲目**」里的**人声主旋律**，
> 按 **`Ctrl+A`** 全选这条轨，然后在「歌词」框里**把整段歌词贴/打进去** ——
> 会**一个字一个音符**按时间顺序铺下去。歌词框这时会变紫并提示
> 「已选中 N 个音符」，就是在告诉你现在是这个模式。
>
> **③ 从 LRC / 文本导入**：点 **「导入歌词…」**（或按 **`Ctrl+L`**），
> 贴进去让它按时间（LRC）或按顺序（纯文本）自动铺开，再回卷帘上微调。
>
> **分词方式**（工具栏「分词」下拉，② 和 ③ 都受它影响）：
> * **自动（默认）**：中文**逐字**分（`我爱你` → 我 / 爱 / 你），英文按词分；
> * **按空格**：只按**空格**分词（`wo ai ni` → wo / ai / ni）；
> * **逐字符**：每个字符都算一个（`wo ai ni` → w / o / a / i / n / i）。
>
> ⚠️ **自动模式下「一个英文单词」算一个单元**：直接输入 `opendoor` 只会落到**一个**
> 音符上。想让它拆成 `o`/`pen`/`door`，要用下面两个记号。
>
> **两个记号要会用**：
> * **`‿`（就是减号 `-`）= 延音符**，表示"接着上一个音节的音往下唱"，用于一字多音；
> * **`⁀`（就是加号 `+`）= 拆音节**，表示"本音符唱上一个词的下一个音节"
>   （`opendoor` 填成 `opendoor` `+` `+`，三个音就分别唱 `o` / `pen` / `door`）。
>
> 这两个按钮在**多选**时会把记号写到**所有选中**的音符上（把一段都标成延音很方便）。
>
> 也可以点 **「导出 LRC」** 把当前歌词导成 LRC 文件。

> **导出什么，你自己勾。** ③ 顶部那三个勾选框：
>
> * **人声主旋律** —— 默认**唯一勾上**的；
> * **器乐旋律**；
> * **和弦**。
>
> **默认只导出「人声主旋律」一条轨。** 想要器乐或和弦，自己把对应的勾点上。
> 勾选改完**不需要重跑推理**，点保存（或直接点导出）就生效。
> 点导出时程序会先按当前状态重新生成，再下载 —— 不会再让你下到上一次的旧文件。
>
> **如果你没给人声主旋律填歌词**，点导出时会弹一个提示框问你
> 「未填歌词，所有音符均为 la」，可以选**返回去填**或**继续导出**。
> **器乐旋律与和弦不受影响**，留空就行。
>
> **关于重叠的音符**：虚拟歌姬（Synthesizer V）一条轨里不允许音符重叠。
> 程序会检查**每一条轨**，凡是同时响着多个音的，就**自动拆成
> `名字1`、`名字2`、`名字3`…**（同一时刻最多几个音同时响，就拆几条），
> **一个音都不会丢**；本来就不重叠的轨保持原名不变。
>
> 实际用起来：**和弦**本来就是多个音同时响，所以勾上「和弦」后看到
> `和弦1`…`和弦5` 是正常的，不是 bug。
> 而**人声主旋律**和**器乐旋律**是单声部旋律线，正常情况下**不会**被拆；
> 如果你看到 `主人声1`、`主人声2`，那更可能是这首歌的时值 / 速度识别有问题，
> 可以反馈给我们。

### 底部状态栏（右边两个按钮）

| 元素 | 作用 |
| --- | --- |
| `#任务号` | 当前任务编号；反馈问题时连带它一起发 |
| **清理缓存** | 清空 `output\`（历史任务产物）与 `tmp\`（上传的音频 + 中间文件） |
| **日志** | 展开 / 收起运行日志 |

**清理缓存怎么用**：点一下 → 先算出两个目录各占多少（几个文件 / 多大）→
弹确认框 → 点确定才动手。扒谱进行中按钮是灰的（跑任务时不让删）。

> ⚠️ **这是永久删除，不进回收站，删掉找不回来。** 想留的产物（`.svp` / `.mid` / `roll.json`）
> 先自己拷到别处。两个目录**本身会保留**，下次启动和上传时会自动重建。

### 端口被占用

双击两次 `start.bat` 不会出错：第二次会认出「已经在跑」，直接把浏览器指过去。
如果是**别的程序**占了 8777，改 `settings.json` 里的 `"port"`，
或把 `start.bat` 复制一份、在后面加 ` --port 8888`。

## 3. 产物在哪、怎么用

```
output/<日期时间>_<任务号>/
    export/<歌名>.svp        ← 给 Synthesizer V Studio（格式 version 153）
    export/<歌名>.mid        ← 通用 MIDI
    roll.json                ← 卷帘上你的音符与歌词（③ 的编辑结果）
    score.abc                ← 模型输出的原始乐谱（内部格式，不再作为产物提供）
    transcription.mid        ← 模型原始多轨（人声 / 器乐 / 和弦）
    chords.mid / melody_*.mid / beat.lab / chord.lab / key.lab / structure.lab
    summary.json             ← 这一次的所有参数、耗时、诊断
```

* **SVP**：直接拖进 Synthesizer V Studio 打开即可。
* **MIDI**：任何 DAW 都能开。
* **summary.json**：反馈问题时**请把它一起发出来**，里面有设备、精度、耗时、诊断。

## 4. 出问题了怎么办

**90% 的问题自己就能好**：

* 报「端口被占用」→ 改 `settings.json` 的 `port`
* 报「找不到权重 / 缺 model.safetensors」→ 权重没下完，重跑
  `python tools\download_models.py`（已下好的会自动跳过）
* 报 **`FFmpeg is required to read audio files`** →
  **`ffmpeg` 不在 `PATH` 上**。这是最常见的坑：项目的解码链路只认 `PATH`。
  装好 ffmpeg 并确认 `ffmpeg -version` 能跑；或设环境变量 `FFMPEG_BIN`
  指向任意 `ffmpeg.exe`
* 报 CUDA / 显存相关错误 → 把 `settings.json` 的 `"default_device"` 改成 `"cpu"` 先跑通
* 扒谱中途失败 → 看黑窗口最后几行的报错，连同该任务的 `summary.json` 一起发出来
* 磁盘被占满 / 攒了一堆测试任务 → 点状态栏的 **清理缓存**（永久删除，先看确认框里的数字）

## 5. 隐私 & 安全

* 服务**只监听 `127.0.0.1`**（本机回环），同一局域网的其他人都访问不到。
* 上传的音频放在 `tmp/uploads/`，任务过期会自动清理；想彻底清干净就删掉
  `tmp/` 和 `output/` 两个目录（下次启动会自动重建）。
* 程序**不联网**（只有首次装环境 / 下权重需要），不上传你的任何数据。
