# 填词「锚定」方案评估

当时的结论是：按句切成段、在句内跑单调 DP（`sdp`）比线上逐字贪心好——挂对（hit）从 69.3% 升到 73.4%，和人工版一致的音槽从 40.1% 升到 46.2%，「错一格」这种贪心漂移从 25 个降到 13 个；代价是看不见的字从 14.3% 涨到 18.6%，所以没改默认。同一批实验里，「先钉句首字、再钉句末字」那种严格锚定反而更差（65.6%），因为 23.8% 的句末字根本没有时间戳，拿它当右锚点等于拿一个编出来的位置去锁整句。

这个结论现在只对了一半。它测的是「挂字算法在坏输入上的补丁能力」，而真正的瓶颈不在挂字，在字的时间戳：拿同一套 SheetSage2 音符、只把逐字时间换成 TiFA 给的，线上贪心就从 76.0% 跳到 97.8%（挂歪 75 个降到 0，偏 >1s 从 21 个降到 0）；反过来，字时间还是我们自己那套时，`sdp` 最多把 76.0% 抬到 82.4%。也就是说，`sdp` 能补的只有字时间「大部分对、少数零长度」这一种病，补不了「一个字被给了 4 秒、后面 8 个字全挤在它末尾」那种塌方。完整对照见 [`reports/V2对照-爱情转移.md`](../reports/V2对照-爱情转移.md) 第 3 节。

已经落地的两项都不是挂字算法：零长度字按前后空档插值、切片边界让位给人声（按改前的 14 个工程 4805 字算：hit 68.9% → 84.6%，late 583 → 0，|Δ|>1s 179 → 44），细节在同一份报告的 §6 与 §10。`sdp` 仍然没有改默认，而且优先级进一步下降了——字时间一旦变好，挂字已经不是主要矛盾。

要重跑实验：`scripts/anchor_align_probe.py`（八个变体、自检、人工版对比）。`reports/锚定对齐对照.md` 已经按现在的 14 个工程重算过（4810 字，greedy 70.4%），和当年那张 12 首的表不能直接比：口径没变，但输入的字时间变过一次了。
