# Vocal2Midi 对照与可借鉴项

参考项目：`reference/Vocal2Midi`（Apache 2.0，Copyright 2026 Xiantaidu）。
本文只记录**结论与出处**，用于决定下一次对话要抄什么。

---

## 1. 根本差别：时轴从哪来

```
Vocal2Midi:
  ASR ──只取文字──> G2P 音素序列(.lab)
                          │
                HubertFA 音素级强制对齐   ←── 时轴在这里
                          │
                   每个字的时长（正、连续、单调）
                          │
          GAME 音符模型（吃 known_durations）
                          │
                align_notes_to_words
                          │
                   smart_quantize（DP）

我们:
  SheetSage2 ──> 音符 + 小节表（不知道歌词）
  Qwen3-ASR ──> 文字
  Qwen3-ForcedAligner ──> 字级时间戳（16% 是零长度）
  lyrics.assign_lyrics（事后匹配）
  ✗ 没有量化
```

**关键事实**：`run_qwen_asr_and_fa()` 里 `batch_transcribe_asr` 只用 `res.text`，
时间戳**完全不用**。我们用 LLM 对齐器的字级时间戳，他们有 16% 是零长度——
他们没有这个问题，是因为那条路径不存在。

**出处**：`inference/pipeline/auto_lyric_hybrid.py:133-170`

## 2. 七个具体机制

### ① 音符模型吃字时长（条件生成）

```python
_run_game_inference_batch(..., known_durations_np=known_durations_np, ...)
```
GAME 是**给定字的时长**去推音符的，音符边界从一开始就被字引导。
**无法借鉴**：SheetSage2 不接受字时长输入。

**出处**：`inference/API/game_api.py:400-411`

### ② 边界吸附 + 单调钳制

```python
nearest = argmin(|note_boundaries - word_boundary|)
if |nearest - word_boundary| <= tol:      # tol 默认 0.01s
    candidate = nearest
aligned = clamp(candidate, prev + MIN_GAP, next_word_boundary - MIN_GAP)
```
把**字的边界吸到最近的音符边界**，同时保证严格单调。
`_ALIGN_MIN_GAP = 1e-4`。

**对我们无效**：吸附的前提是输入边界不退化。他们的边界来自音素时长，永远为正、
连续、单调；我们的字有时间戳零长度，两个边界重合 → 钳制判定不可行 → 退回原值。

**出处**：`inference/game/alignment_utils.py:121-137`

### ③ 两套模式按语言选

```python
assign_by_onset=(language or "").lower() == "en"
```
- 中文/日文：**切分**模式——把跨字边界的音符切开按比例分给两个字，相邻同音高合并
  （`alignment_utils.py:205-251`）
- 英文：onset 归属——整个音归"包含它起点的那个字"
  （`alignment_utils.py:148-203`）

我们的 `assign_lyrics` 对应他们的**英文**模式。中文走切分模式更贴近
"一字多音 / 一音多字"的实际。

**出处**：`inference/API/game_api.py:431-438`

#### 实测：切分模式值不值得？（已量过，结论：**暂不设为默认**）

实现了 `lyrics.assign_lyrics_split()`（带兜底：零长度时间戳的字退回"离得最近的音"，
否则切分反而会丢掉这部分字），拿 4 首已经识别好的工程离线对照
（`scripts/split_mode_check.py`，结果落 `reports/切分模式对照.md`）：

| 工程 | 音 | 字 | 零长度 | 现:显示不出来 | 切分:显示不出来 | 切开音 | 新增音 | 改动 |
|---|---|---|---|---|---|---|---|---|
| 光芒 | 324 | 324 | 53 | **19** | 15 | 187 | +196 | **+60%** |
| 相思 | 214 | 204 | 14 | **12** | 8 | 117 | +123 | **+58%** |
| 皮囊 | 397 | 360 | 112 | **50** | 48 | 116 | +146 | **+37%** |
| 巴拉莱卡 | 441 | 600 | 95 | **229** | 38 | 277 | +409 | **+93%** |

（"显示不出来" = onset 的挤占字数 + 两边都有的"落在音符间隙里"的丢弃字数。）

读法：

- **收益只落在"快嘴"上**：巴拉莱卡的显示不出来从 229 降到 38（+93% 音符换来的），
  而《皮囊》花了 +37% 音符只救回 2 个字——它的零长度时间戳有 112/360 = 31%，
  这些字**根本没有边界可切**，切分对它无能为力。
- **代价是谱面**：新增的音符是模型没扒出来的音位，由逐字时间戳补出来的。加上量化会把它们
  再吸到网格上，导进 DAW 之后"听到的"和"写的"就不是一回事了。
- 因此**默认仍然是 onset**（音符一个都不动，模型输出的事实不篡改），
  `assign_lyrics_split()` 作为**候选**留在代码里，`tests/test_lyrics.py` 里有一条测试专门
  锁住"默认不是切分"。

**真要上的话，更可取的是"只切值得切的音"**（例如一个音明显长于中位数、却压了 2 个以上的字），
而不是全曲重切；或者在**歌词轨**上做（原型里歌词轨本来就是按行画的，与音符解耦）。

### ④ 幽灵零长度 rest 占位

```python
new_note_seq.append("rest")
new_note_dur.append(0.0 if covered else end - start)
```
字没分到音符时，如果那段时间已被前面一个长音覆盖，补一个**零长度 rest**，
让"字槽/音槽"继续对齐又不引入实际时间。

**出处**：`inference/game/alignment_utils.py:171-177, 199-202`

### ⑤ DP 时值量化（★ 最值得抄）

`smart_quantize.py`，纯整数 DP，无模型依赖。

- **记录链**：音符按时间排序，**相邻音符之间的静音也做成 gap record**，
  音符合静音串成一条头尾相接的链。重叠音符直接判失败。
- **每个记录只有一个自由度**：占用的列数 `j ∈ [max(1, dcols-16), dcols+16]`
- **打分**（最大化）：

  | 项 | 式子 |
  |---|---|
  | 起点 | `M(pos_start) − 0.5·((pos_start−orig)/BAR)²` |
  | 时长 | `−((j·GRID − orig_dur)/BAR)²` |
  | 终点 | `M(pos_end) − 0.5·((pos_end−orig)/BAR)²` |

- **M(p) 节拍重要性阶梯**（p = 绝对位置 mod BAR）：

  | 位置 | 分值 |
  |---|---|
  | 小节头 | 0 |
  | 半小节 | −0.05λ |
  | 四分 | −0.1λ |
  | 八分 | −0.2λ |
  | 十六分 | −0.4λ |
  | 其他 | −0.8λ |

- `λ = 0.5 × 10^(simplicity/5)`，`simplicity ∈ [0,5]` 当力度滑杆
- 网格：`BAR = 705_600_000`，`GRID = BAR/32`（32 分音符）
- DP 两张表 `s0[r][c]`（记录 r 从列 c 开始）/ `s1[r][c]`（到列 c 结束）；
  最后一条的终点强制在 `colCount-1`，回溯
- 写出后所有边界都落在 32 分网格上，且每条记录的终点 = 下一条的起点
- `smart_quantize_musical(notes, simplicity, ticks_per_quarter)` 自动换算 PPQ

**我们的现状**：`project.json` 的音符 tick 直接来自秒的线性插值，落在任意 tick 上，
**完全没有量化**。没有它，卷帘上音符落不到网格，也导不进 DAW。

**出处**：`inference/quant/smart_quantize.py`（全文 275 行）

### ⑥ 参考歌词走音素模糊匹配

`create_lyric_matcher(language, original_lyrics)` → ASR 出音素、参考歌词也转音素 →
在音素序列上做窗口匹配（`_align_direct_phoneme_moras_with_matcher`）。
依赖 `inference/LyricFA/tools/ZhG2p.py` / `JaG2p.py`。

**价值**：同时治对齐器的错字和零长度——字不由 ASR 提供，对齐器只需定位、不需猜字。

**出处**：`inference/API/lfa_api.py:118-152, 218-230, 231-389`

### ⑦ 切片用 4 种策略

`grid_search_slice` / `heuristic_slice` / `pitch_based_slice` / `default_slice`。
我们只用 `structure.lab` 段落。

**出处**：`inference/API/slicer_api.py`

## 3. 问题构成实测（《光芒》324 字 / 324 音）

| 喂进去的字 | 挂字 | 没分到字的音 | 丢掉的字 |
|---|---|---|---|
| 全部 324（含 53 个零长度）| 295 | 14 | **29** |
| 只喂非零长度的 271 | 257 | **39** | **14** |

结论：**约一半（15 个）是零长度时间戳造成的，另一半（14 个）来自别处**
（字比音多的区段、窗口没覆盖）。

## 4. 建议的采纳顺序

| 借鉴 | 收益 | 成本 | 建议 |
|---|---|---|---|
| **⑤ DP 时值量化** | **最高**。完全没有，是"音符落到网格"的最后一块 | 纯函数，无模型依赖，可直接移植 + 单测 | **✅ 已完成**（见 `docs/音符量化规格.md`） |
| ⑥ 参考歌词音素匹配 | ~~高~~ → **实测无效** | 需 G2P 依赖，中等 | **❌ 别做**（见下面 §6 的实测） |
| ③ 中文走切分模式 | 中。更贴近中文一字多音 | 需改音符（**会动模型输出**） | 看效果再定 |
| ② 边界吸附 | **低**。输入退化，吸不动 | — | 不做 |
| ① 音符模型条件生成 | 无法借鉴 | — | 不做 |

## 5. ⑤（DP 时值量化）落地记录

| 项 | 结果 |
|---|---|
| 代码 | `src/sheetsage2_webui/quantize.py`（引擎 + 项目适配） |
| 测试 | `tests/test_quantize.py` 31 项 |
| 规格 | `docs/音符量化规格.md` |
| 真实数据 | 10 个工程 / 20 条轨道，网格率 **1.2%~98% → 100%**，失败轨道 **0** |
| 相对参考的改动 | ①小节长可参数化（2/4、6/8 不再按 4/4 打分）②空窗口预检 + 失败诊断 |

**踩到的两个坑**（写在这里省得下次重踩）：

1. 参考实现里某条记录的合法列窗口为空时，`for c in range(wlo, whi)` 一次都不进，
   那张 DP 表就是空的，回溯**可能给出越界结果**。必须先挡空窗口。
2. **`simplicity=0` 不等于"不动"**：λ=0.5 时节拍阶梯仍然生效，DP 会拿位移换强拍点。
   报告里必须给出位移统计（`note_shift_seconds`），不能只报"已量化"。

## 6. ⑥（参考歌词音素匹配）的实测结论：**不做**

原先的判断是"⑥ 同时治错字和零长度"。我们直接做了对照实验
（`scripts/probe_ref_align.py`）：把**参考歌词**（而不是 ASR 文本）喂给
`Qwen3ForcedAligner.align(audio, text, language)`，看零长度时间戳是否减少。

《光芒》三个切片的结果：

| 切片 | 参考文本喂进去 | 对齐器吐出 |
|---|---|---|
| 0（0–85.7s，126 字） | 零长度 10% | 零长度 **10%** |
| 1（85.7–159.6s，134 字） | 零长度 15% | 零长度 **15%** |
| 2（159.6–195.2s，64 字） | 零长度 31% | 零长度 **31%** |

**完全一样。** 切片 0 的时间戳与现有（ASR 驱动）结果逐字相差中位 0.010s——
也就是说**对齐器对短促/弱唱的音节本来就给不出时间，与喂什么文本无关**。

所以零长度不是"猜错字"造成的，⑥ 治不了它。正确的做法是在**填词阶段兜住**：

- 零长度字当成一瞬间，给对称窗口（已有）
- 段落的音比字少时，多出来的字记进 `absorbed_chars` 并告警（新增，见
  `src/sheetsage2_webui/lyrics.py`）

**顺带发现的真 bug**（收益远大于 ⑥）：`assign_lyrics` 的 `last_pos` 把"排序后的位置"
当成了"音符下标"用，导致扫描起点错位、29/324 个字被误报为"没有重叠"而丢掉。
详见 `docs/交接-下一次对话.md` §5。
