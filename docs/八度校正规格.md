# 八度一致性校正规格

> 实现：`src/sheetsage2_webui/octave.py`（接在 `pitch.py::apply` 里，默认开）
> 测试：`tests/test_octave.py`（16 项）+ `tests/test_octave_samples.py`（7 项，真实样本）
> 样本：`samples/对齐/王朝1982,朱旭BooBoo - 我本将心向明月.svp`（机扒）与 `…（人工）.svp`
> 相关：`docs/WebUI问题清单.md` §1（整体高一个八度）、§6（本文档对应的条目）

---

## 0. 一句话

模型的音高**音级是对的、八度不可靠**。整体偏高一个八度由 `pitch.py` 统一 −12 解决；
**"只有某一段低一个八度"** 是 −12 治不了的局部错误，这里按一条自证的不变量修：

> **同一段旋律在歌里出现多次时，音高只允许差 0，不允许差一个八度。**

哪一次是错的不靠猜：**改动音符最少的那一种**（= 让证据最多的那一拨保持不动）；
两个候选一样多（平票）就**不动手**。

## 1. 为什么必须做

### 1.1 那对 SVP 的实测差

`samples/对齐/` 里是同一首歌的两个版本：`.svp` 是本项目跑出来的机扒工程，
`（人工）.svp` 是用户在 Synthesizer V Studio 里修过的。逐音比对（按 onset 对齐）：

| 项 | 机扒 | 人工 | 结论 |
|---|---|---|---|
| 音符数 | 381 | 379 | 差 2（人工合并了几处）|
| onset 逐 tick 相同 | — | **372 / 381** | **不是"时间对不上"** |
| 时值分布 | 0.25/0.5/1.0 拍为主 | 同 | 同上 |
| 音高差 | — | **76 个音正好 +12** | **是八度** |
| 其余 4 个位置的差 | — | {+7,+8,+10,+14} | 出在人工合并/新增音处，不是八度 |

同一段副歌在歌里出现三次，机扒与人工给的是：

| 出现位置 | 机扒 | 人工 |
|---|---|---|
| 第 72~104 拍（section 0） | 66 | 66 |
| 第 168~201 拍（section 1） | **54** | **66** |
| 第 248~281 拍（section 2） | 66 | 66 |

抬完之后，section 1 的副歌与 section 2 的**逐音相同**（54/54 命中）——
人耳能听出来的"这一段唱低了"，就是这 12 个半音。

### 1.2 为什么整体平移治不了

`pitch.py` 的 −12 是**整条旋律一起动**。机扒版里三次副歌是 66 / 54 / 66：

- 一起减 12 → 54 / 42 / 54（还是差一个八度）；
- 一起不减 → 66 / 54 / 66（还是差一个八度）。

**任何整体平移都消不掉段与段之间的相对八度差**，所以必须逐段判。

### 1.3 校正之后

| 指标 | 校正前 | 校正后 |
|---|---|---|
| 与人工版逐音相同 | **292 / 372（79%）** | **361 / 372（97%）** |
| 人工改过的 80 个音里跟对 | — | **69 个** |
| 被改动的音 | — | 73 个，全部 +12 |
| 改动范围 | — | 只在 103~198 拍这两段重复段里 |

## 2. 算法

### 2.1 切乐句

同一轨内，两个音之间静音 ≥ `REST_GAP`（0.6s）就断开。
0.6s 刚好卡在"换气"（≈0.67s 的八分休止）之上，所以 90 BPM 的曲子会切成
"主歌一句、副歌一句"，而不会被换气切碎。

### 2.2 找重复

两两乐句做 **音级**（`pitch mod 12`）序列匹配（`difflib.SequenceMatcher`，
天然容忍插入/删除），要求：

1. 匹配块 ≥ `MIN_BLOCK`（8 个音）——短块不算数；
2. 块内的**音程走向**也要一致（≥ `MIN_CONTOUR_RATE` = 80%，容差 ±1 半音）——
   否则"音级碰巧一样"会造出假重复；
3. 把块按"差值恒定"再切成小段：副歌头是对的、尾句低一个八度时，
   一个块里会混着两种差值；
4. 相邻且**同差值**的小段并回去（否则 13 个音的重复会被块边界切成 8+5，两段都不够长）；
5. 只留差值**正好是整八度**（`|Δ| ≥ 12` 且 `|Δ mod 12| ≤ 1`，且 ≤ ±2 个八度）的段。

### 2.3 解约束

每处重复给段与段之间建一条 `k_A − k_B = Δ八度` 的约束，
**并查集**把互相咬合的段连成一个**分量**；分量内部各段的相对偏移 `base` 由约束唯一确定。

段是"由**所有**重复段的端点共同切出来的最小片段"——这样同一个音被不止一对重复引用时，
它们不会被互相排斥，而是被连到一起。

### 2.4 挑整体平移 K

每个分量还有一个自由度 K（`k = base + K`）。判据只有一条：

> **改动的音符数最少。** 也就是"让证据最多的那一拨保持不动"。

用加权中位数就能一次算出来；实现里直接枚举候选 K（`K ∈ {−base} ∪ {0}`）比较。
**如果两个候选改动的音一样多 → 平票 → 这一处不动。**
那时分不清"抬前一次"还是"压后一次"，不猜比猜错好（`光芒` 的器乐就是这种情况）。

### 2.5 应用

`p_n += 12·k_n`，只动音高，时间一个都不碰。

## 3. 参数

| 常量 | 值 | 含义 | 调它的后果 |
|---|---|---|---|
| `REST_GAP` | 0.6s | 乐句切分阈值 | 变小 → 换气也断句，重复更难匹配；变大 → 主歌副歌粘成一句 |
| `MIN_PHRASE_NOTES` | 6 | 短于此的乐句不参与匹配 | — |
| `MIN_BLOCK` | 8 | 一次重复至少要覆盖这么多音 | **实测调到 3~6 会明显变差**（见 §5）|
| `MIN_CONTOUR_RATE` | 0.8 | 音程走向一致的最低比例 | 调低 → 假重复变多 |
| `MAX_OCTAVES` | 2 | 最多认几个八度 | — |
| `BIG_LEAP` | 11 | "大跳"的报告阈值 | 只影响报告，不做判定 |

`TIME_TOLERANCE`（5ms）是**查表**用的：MIDI 的起始时刻是从 tick 换回来的，
和 lab 差 ~1e-4 秒，按时间最近邻取这一份局部平移时要用它兜住。

## 4. 落点与产物

八度校正和整体 −12 一起在 `pitch.py::apply` 里落地，**先局部后整体**（都是整八度，可交换）：

```
engine.transcribe() → pitch.apply(semitones=-12, octave_fix=True) → tick 域工程 / SVP
```

于是所有产物共用同一份 `OctavePlan`：

| 产物 | 怎么用这份计划 |
|---|---|
| `melody_full.lab` / `melody_vocal.lab` / `melody_instrumental.lab` | 按行里的起始秒查表（`melody_full` 用第 4 列的轨道号，另外两个由文件名定）|
| `melody*.mid` / `notation/song_melody.mid` / `transcription.mid` | 按 `note.start` + 轨名查表；`transcription.mid` 的和弦轨照旧跳过 |
| `playback.json` | 按 `note["start"]` + 轨名查表，和弦轨跳过 |
| `project.json` 的音高、卷帘、导出的 SVP | 从改完的 lab 一路派生，自动跟着对 |
| `score.abc` | 重建（旋律 MIDI 已经改过）|

**选项**：

- 默认开。`pipeline.run(octave_fix=False)` / 命令行 `--no-octave-fix` 关掉它；
  关掉时 `project.json` 的 `pitch.octave.enabled == False`，报告里也不会有一行。
- `project.json` 的 `pitch.octave` 里能看到 `moved_notes` / `moved_octaves` / `groups` /
  `links` / `big_leaps_before|after`，报告里 `pitch` 那一段同步可见。

## 5. 在既有工程上的行为（实测）

对 `output/` 里 13 个真实工程跑一遍（脚本见 §6）：**11 个一个音都不动**，
动的 3 个是：

| 工程 | 改动 | 依据 |
|---|---|---|
| **王朝1982…我本将心向明月** | **82 音**（人声 73 + 器乐 9）| 三次副歌出现里一次低八度；器乐引子三次里有两次同高 |
| 萧敬腾 - 皮囊 | 9 音（人声）| 同一句出现 4 次，3 次在 60~67、1 次在 72~79 → 把那次压回来 |
| 凤凰传奇 - 光芒 | **0**（平票不动手）| 器乐两次出现各 48 个音，一样多 → 不猜 |
| 其余 10 个 | 0 | 没有"差整八度的重复段" |

`MIN_BLOCK` 的实测（我本将心向明月）：

| `MIN_BLOCK` | 与人工版相同 | 改动音数 | 大跳 |
|---|---|---|---|
| 3 | 328/372 | 139 | 3 → 19 |
| 4 | 341/372 | 109 | 3 → 16 |
| 5 | 352/372 | 88 | 3 → 9 |
| **8（默认）** | **361/372** | **82** | 3 → 7 |
| 12 | 361/372 | 73 | 3 → 6 |

放宽到 3~6 会让假重复把更多音拖下水，所以钉在 8。

## 6. 复核办法

```powershell
# 单元 + 样本回归（后者直接读 samples/对齐 的两个 .svp，不依赖 output/）
.\.venv\Scripts\python.exe -m pytest tests/test_octave.py tests/test_octave_samples.py -q

# 全量
.\.venv\Scripts\python.exe -m pytest tests -q

# 对 output/ 里所有既有工程扫一遍"会不会乱动"
.\.venv\Scripts\python.exe - <<'PY'
import sys; sys.path.insert(0, "src")
from pathlib import Path
from sheetsage2_webui import octave
for job in sorted(Path("output").iterdir()):
    lab = job / "melody_full.lab"
    if not lab.is_file():
        continue
    rows = octave.parse_lab_rows(lab.read_text(encoding="utf-8"))
    _shifts, plan = octave.plan(rows)
    print(f"{job.name}: 改动 {plan.stats.moved_notes} 音 "
          f"（重复段 {plan.stats.links} 处，分量 {plan.stats.groups} 个）")
PY
```

对某一份工程看细节（哪几处重复、哪个分量选了哪个 K）：

```powershell
.\.venv\Scripts\python.exe -c "import sys;sys.path.insert(0,'src');from pathlib import Path;from sheetsage2_webui import octave;rows=octave.parse_lab_rows(Path(r'output/王朝1982_朱旭BooBoo_-_我本将心向明月/melody_full.lab').read_text(encoding='utf-8'));st=octave.Structure.build(rows);[print(r.size, r.octaves, round(st.segments[st.seg_of[r.a[0]]][0])) for r in st.repeats]"
```

## 7. 已知不完美

1. **还有 11/372 个音没跟对人工版**，都是重复段**两端**各差一两个音
   （机扒的匹配块比人工改的范围少一两个音）。要治得动"把匹配段往外延伸"，
   但延伸会带来假阳性，暂时不动。
2. **器乐轨没有真值**。`samples/对齐` 的人工版只导了人声轨，
   所以器乐的 9 个音是"按同一套规则推出来的"，没有人工版可以对照。
3. **平票一律不动**，宁可漏。`光芒` 那 48 个音可能确实有一处是错的，
   但"抬前一次"和"压后一次"代价相同，没有第三种证据（干声 / 简谱）时不猜。
4. **绝对八度仍然不保证**。这里只保"段与段之间一致"，绝对音区还是
   由 −12 那个固定偏移决定；要定案得用干声（见 `docs/WebUI问题清单.md` §1 的复核办法）。
