### 1.3 ffmpeg：用裁剪版，实测四条用法全过

参考项目里那份 `reference/Vocal2Midi/ffmpeg.exe` 是**专门裁剪的静态构建**（7.1.1，**2.2 MB，无 DLL**）：

```
--disable-everything --enable-small --extra-ldflags=-static
--enable-protocol='file,pipe'
--enable-demuxer='mov,mp3,ogg,flac,wav,aac,asf,matroska,aiff'
--enable-decoder='aac,aac_latm,mp3,mp3float,flac,vorbis,opus,alac,wmav1,wmav2,wmapro,pcm_*'
--enable-muxer='wav,ipod,pcm_f32le'      # ← 注意：没有 s16le
--enable-filter='aresample,format,aformat,abuffer,abuffersink,buffer,buffersink'
```

本项目**只调 ffmpeg、不用 ffprobe**（全仓库 grep 过），四处用法实测：

| 用法 | 结果 |
|---|---|
| `bootstrap.find_ffmpeg()` 能不能找到它 | ✓（`bootstrap.py` 的**第一优先候选里已经有 `runtime/ffmpeg/bin`**，不用改代码） |
| 波形 `media.compute_peaks()` | ✓（见下，改了一行） |
| 切片 → 16k 单声道 wav（歌词识别按段落切） | ✓ 24000 采样 @16kHz |
| `-f f32le pipe:1`（SheetSage2 自己的解码） | ✓ 与完整版**逐采样一致**（max 1.6944 / p99 1.2344） |

**为了让裁剪版够用，改了 `media.py` 一处**：波形的解码从 `-f s16le` 改成 **`-f f32le`**
（裁剪版只留了 `pcm_f32le`），并显式 `clip(0,1)`：

- `-ac 1` 的下混是 **L+R 不除 2**，所以浮点会超过 1.0（实测《光芒》峰值 **1.694**、约 **4%** 采样越界）；
- 以前走 s16le 时这些值在 16 位里**饱和**掉了，所以显示一直是 0~1 —— 现在显式 clip 回来，**视觉与旧行为一致**（实测峰值仍 1.000）；
- 完整版 ffmpeg 也支持 f32le，所以这个改动对现有环境**无副作用**（234 项测试全过）。

> ⚠️ **边角**：裁剪版的 demuxer 少三个 → **`.wv`（WavPack）/ `.ape`（Monkey's Audio）/ `.caf`** 这三种
> 上传**解不了**，而 `jobs.AUDIO_SUFFIXES` 现在是收的。要么自己再裁一份（加上
> `wavpack,ape,caf` 的 demuxer/decoder，也就几 MB），要么按可用的 ffmpeg 能力
> **动态收窄上传后缀**并给出人话提示。

## 2. 首次运行要做的检测与下载（`webui.bat` → 引导脚本）

内测者的体验：**解压 → 双击 `webui.bat` → 看着进度条 → 浏览器自动打开**，
全程不敲命令。每一步都要：**已存在就跳过** → 显示进度 → **sha256 校验** → 断点续传/重试 → 失败给人话。

1. **建环境**：包内自带 `runtime\python\python.exe -m venv .venv`（**不用 uv、不用联网装 Python**）。
2. **torch / torchaudio**：从 `downloads.json` 的直链下（南大镜像，带 sha256）；本地留了轮子就直接用。
3. **项目依赖**：`.venv\Scripts\python.exe -m pip install -e ".[web,svp]" "transformers==4.57.6" qwen-asr …`
   —— **走国内 PyPI 镜像**（清华/阿里），不然容易卡住。
4. **模型**：ModelScope API 列文件 → 下载到 `models/`（**支持最小集/全量**，可续传）。
5. **自检**：`import torch` + `torch.cuda.is_available()`；不可用就提示走 CPU（很慢但能开）。
6. **起服务 + 开浏览器**（现有 `scripts/launch.py` 已经会：端口占用自动换、缺前端就构建）。

## 3. 待定的设计问题（开工前定）

1. **模型的档位**：最小集 / 全量 / 让内测者勾？——1.7B 一个人就差 **4.5 GB**，
   而它换来的是"专有名词全对"（布达拉宫/喜马拉雅山/格桑花）。
2. **`.wv/.ape/.caf`**：再裁一份带这三个 demuxer 的 ffmpeg，还是收窄上传后缀？（见 §1.3）
3. **GPU 驱动**：cu130 要较新驱动（本机 591.86 / CUDA 13.1）。老驱动的同好要么升驱动，
   要么 CPU（全曲扒谱基本不可用）。要不要在预检里直接说清楚？
4. **清单格式**：`下载链接.txt` 是人读的、且模型是页面链接 → 建议换成 `downloads.json`
   （每项：`target` / `url`（或 `repo+revision`）/ `bytes` / `sha256` / `optional`），
   下载器、文档、校验都用它。**这是开工第一步。**
5. **`uv.exe` 要不要也塞进去**（65 MB）：不塞也行（§2 第 1 步已经不需要它），
   但如果以后要"给已有 Python 环境的人一条旁路"，它有用。
6. **许可证**：SheetSage2 权重是 **CC BY-NC 4.0（非商业）**；打包分发要带 `NOTICE` + 原许可说明；
   自带的裁剪版 ffmpeg 也要按 FFmpeg 的许可附上构建配置说明。别让"内测"变成对外分发。
7. **预检**：开始下载前要不要先检查磁盘空间 / 网络连通性 / 是否已经有可用环境？

### 5.3 为了让 ffmpeg 随包跑起来，改了代码

本机的 ffmpeg 在 `D:\ffmpeg\bin`，**和项目不在一起**；老逻辑是"`shutil.which` 先、开发机固定路径兜底"，
到了同好机器上就是"找不到"或"用错版本"。现在 `bootstrap.find_ffmpeg()` 的顺序是：

**环境变量 → 随包自带（`runtime/ffmpeg/bin/ffmpeg.exe`）→ PATH → 开发机固定路径**

- 新增 `bootstrap.bundled_ffmpeg()`；找到随包那份时把它所在目录**塞到 PATH 最前面**
  （SheetSage2 自己是按 PATH 找 ffmpeg 的）；
- 随包那份**故意压过 PATH**：内测包带的是实测过的裁剪版，不该被同好机器上别的 ffmpeg 顶掉；
- 实测（包里起真服务）：`/api/env` 回的 `ffmpeg` 就是
  `<包>\runtime\ffmpeg\bin\ffmpeg.exe`。
