# 模块结构

> 落地日期：2026-11-13。方案与验收标准见 [`261113 模块化拆分与重构计划.md`](261113%20模块化拆分与重构计划.md)。
> 这份文档描述**现在的**边界与依赖方向；“为什么这么切”写在计划里。

## 1. 一句话

后端按“值对象 → 存储 → 调度 → 路由”单向依赖，`jobs.py` 收成**门面**（组装 + 兼容转发）；
前端 `useStudio` 收成**聚合入口**，状态与副作用各自有唯一所有者；测试按被测职责分文件。

## 2. 后端（`src/sheetsage2_webui/webui/`）

```
job_errors.py     作业异常（取消 / 上传被拒 / 前置未满足 / 只读 / 乐观锁）
job_options.py    参数面板的唯一真源：spec、默认值、校验、标签（纯函数）
job_text.py       人话格式化：秒 → “12 分钟”、字节 → “1.2 GB”
job_files.py      文件名收敛、工程目录原子认领、产物扫描、内容指纹、流落盘
job_models.py     领域对象：Job / StageRun / Event / Progress + 状态常量
job_storage.py    启动恢复与只读导入、job.json、manifest、产物隔离、打包、清理
job_trash.py      回收站：挪进/列出/恢复/永久删/保留策略/定时清理
job_backup.py     整库备份与导入的协调（归档格式仍在 backup.py）
job_scheduler.py  队列 / worker / 看门狗 / 阶段生命周期 / 完成门禁
jobs.py           门面：JobManager 组装 + 旧符号转发 + 工程级策略（参数/音源/删除/备份）
app.py            应用工厂：依赖组装、安全中间件、生命周期、静态资源、/api 兜底 404
routes/           jobs / media / exports / system（+ _shared：ApiDeps 与小工具）
runner.py         RunnerSession：扒谱与歌词两个阶段、进度翻译、产物自检（+ pick_asr_model 旧路径转发）
runner_models.py  模型持有者：懒加载、按工程参数重载、用完还显存
```

依赖方向（**没有环**，已用 AST 扫过全部 `src/`）：

```
job_errors ─ job_options ─ job_text ─ job_files ─ job_models
                                     ↘ job_storage ↘ job_trash ↗ job_backup
                                                     ↘ job_scheduler
                                                            ↘ jobs.py (门面) ↘ routes/ ↘ app.py
runner_models ─ runner ───────────────────────────────────────────↗
```

几条硬约束：

- **领域对象不碰磁盘、不起线程**：`job_models` 只依赖异常、参数和布局常量；
- **存储不管理线程**：`job_storage` 只认 `Job` 与路径，恢复时把结果**交回**管理器登记；
- **调度器不认识管理器**：`Scheduler(root, store, lookup=manager.get, ...)` 只要一个按 id
  取 job 的回调，磁盘写入走传进来的 `JobStore`；
- **router 导入时没有副作用**：依赖集中在 `routes/_shared.ApiDeps`，由 `create_app` 造好传进去，
  不在模块导入时建线程、加载模型或读用户目录；
- **单一状态所有者**：工程列表在 `JobManager`（`_jobs` / `_order`），事件流在 `Job` 自己
  （`events` + `seq`），派生缓存只认 `artifacts_rev`；
- **兼容转发只有两处**：`jobs.py`（门面，拆分前的旧符号全保留）和 `runner.py` 的
  `pick_asr_model`（公开名字，历史就在那里）。新代码不要往这两处加东西——它们只负责
  让老导入路径不断，不负责承载新逻辑。

### 文件规模

运行时文件（不含 `vendor/` 与构建产物）中，除下面这一处外都低于 1000 行：

| 文件 | 行数 | 说明 |
|---|---:|---|
| `asr.py` | ~1010 | **算法文件，按计划 §2 不拆**：Qwen3-ASR 调用、TIFA 对齐、LRC 解析各是一段，共用同一套切片与语言归一化；拆开会把“一次识别的上下文”切成三份，收益小于风险。改它时注意这是全项目最长的自有文件。 |
| `tempo.py` | ~857 | BPM 估计/吸附/拍号，一条算法链。 |
| `lyrics.py` | ~851 | 填词与转音处理，一条算法链。 |
| `jobs.py` | ~678 | 门面：组装 + 工程级策略。 |
| `webui/runner.py` | ~668 | 两个阶段 + 进度翻译 + 产物自检（模型持有已下沉到 `runner_models`；`pick_asr_model` 为兼容旧导入路径在此显式转发，就只有这一行）。 |

> 行数是**复查线**不是指标：`stages/golden` 之类的拆分如果只是把 900 行切成 3 个 300 行、
> 却让读代码要在三个文件之间跳，那就没拆（计划 §10 最后一行）。

## 3. 前端（`web/src/`）

```
composables/
  useStudio.ts       聚合入口：接线 + 跨模块编排（切工程/删工程/init/存活探测）
  useJobs.ts         工程列表、当前工程、快照刷新、卷帘与波形数据
  useJobEvents.ts    SSE 订阅/续传/重连、事件补丁、兜底轮询、取消后的收尾轮询
  useUploads.ts      拖文件建工程、干声、上传进度
  useTrashBackup.ts  回收站与整库备份导入
  logs.ts            日志行（专门用来打断依赖环）
  useAudio.ts        播放器
styles.css            样式入口：只做 @import（顺序 = 级联顺序，改之前先读注释）
styles/
  base.css            * 重置与字体栈（最先）
  tokens.css          :root 颜色/间距/尺寸令牌（组件样式里不写死色值）
  layout.css          顶栏、侧栏、主区栅格
  components.css      通用按钮、只读标记、下载菜单、导出弹窗
  lanes.css           音轨、波形、播放头
  stages.css          流水线、阶段卡、耗时预估、参数面板
  results.css         结果面板与卷帘里的歌词/和弦
  panels.css          日志抽屉、拖拽提示、删除确认/回收站弹层、歌词源抽屉
```

- **作业快照只有一个所有者**（`useJobs`）：组件读 `jobs` / `active`，不许自己复制一份；
- **SSE 只有一条通道**（`useJobEvents`）：事件序号续传、旧事件过滤、进度只增不减、新运行归零，
  规则在 `progress.ts`（纯函数，有单测），事件落库的地方只有 `applyEvent`；
- **上传/回收站/备份各自维护请求状态**，不复制作业领域状态；
- 样式拆分**只做连续切片**，导入顺序与原 `styles.css` 段落一一对应——拆完的构建产物 CSS
  内容哈希与拆前一致（`index-jcosVW5o.css`），这是级联顺序没变的证据。

## 4. 测试（`tests/`）

```
support_webui.py           共用夹具：假 runner、make_client、等待函数、真 WAV 样本
test_webui_jobs.py         状态机 / 队列 / 阶段生命周期 / 参数与作废 / 完成门禁 / 看门狗
test_webui_routes.py       HTTP 契约：状态码、JSON 形状、SSE、下载与 Range
test_webui_storage.py      恢复与只读导入、job.json、manifest、原子写、缓存失效
test_webui_trash_backup.py 回收站：软删/恢复/彻底删除/保留策略/定时清理
test_webui_p1.py           乐观锁、切片、重复入队、磁盘与清理、探针（P1 风险）
test_webui_p2.py           耗时预估、备份包内容与恢复（G20/G22）
```

**故意不用 `conftest.py`**：`support_webui.py` 是显式导入的工具模块，看得见谁在用；
`conftest.py` 一旦变成大杂烩，改一行的爆炸半径就是整套测试。

前端单测在 `web/test/`（`npm test`），覆盖 API 契约、进度单调性、参数面板、拖拽拆分，
以及这次拆分出来的 `useJobs` / `useJobEvents` / `useUploads` / `useTrashBackup`。

npm run build

> `.\.venv\Scripts\pytest.exe` 是 uv 的 trampoline，直接调用会报
> `uv trampoline failed to canonicalize script path`；用 `python -m pytest` 或
> `.\.venv\Scripts\python.exe -m pytest`。
