## 0. 结论

**中文已经从「不合格」追到「差一点」**：token hit **92.7%**（验收 ≥95%，差 2.3pp）、
marker **82.2%**（≥90%，差 7.8pp），hidden 1.2%、|Δ|>1s 0.5% 都已达标。

| 判据 | 验收线 | 现状 | |
|---|---:|---:|---|
| Token hit（exact） | ≥95% | **92.7%**（5058/5456） | ✗ 差 2.3pp |
| ±1 音容差 | — | 95.3% | 参考 |
| Hidden | ≤3% | **1.2%**（65） | ✓ |
| 边界 \|Δ\|>1s | ≤1% | **0.5%**（28） | ✓ |
| `+`/`-` marker | ≥90% | **82.2%**（396/482） | ✗ 差 7.8pp |
| Line exact | ≥85% | 未测 | — |

这 19pp 的提升来自两处（都在挂字层，没碰模型）：

1. **中文改走字级单调 DP**（`lyrics._align_chars_dp`）：贪心在 ±0.2~0.4s 的字时间抖动下
   会把一个字放错，然后整段错位到下一个空音；DP 从全局代价上消掉了这种级联。
   单独这一项（offset 不变）是 73.6% → 77.4%。
2. **offset 估计换算法**（`bench.estimate_offset`）：原来是「用对齐结果搜 offset」，
   等于让贪心把自己的偏好写成时间基准（《赵本山》被偏到 +0.42s、《梦不落》差 0.2s）。
   改成「字起点与音符起点重合最多」后，赵本山 11.6% → **97.8%**、梦不落 18.9% → 86.8%。
   这一项贡献了剩下的大头。

`exact ≥95%` 的歌现在是 **8/15**（赵本山、小炎、薛之谦、范玮琪、问天、朋友的酒、
元若蓝、蒋大为），最差的是杨洪基 75.0%（只有 76 个 head）。

**样本分层**（`bench_score.py` 默认就这样分）：

| 桶 | 首数 | 规则 |
|---|---:|---|
| 主指标 | 15 | 进验收 |
| 文本不一致 | 2 | `text_similarity < 0.7`：巴拉莱卡 51.9%、皮囊 55.2%（人工词 vs ASR 词不是同一份） |

## 1.2 混唱（中英混合）：能修到哪一步

**现状**：`assign_lyrics` 的英文词级 DP 要求**全部** token 都是拉丁/假名，混唱只要有一个
汉字，整首就走字级 DP——英文词被当成「一个字占一个音」。《梦不落》的 `everywhere`
（人工 `everywhere + + we`）在旧实现里会把后两个音让给 `we`，整句前移 2 个音。

4 首含英文的样本，按 token 分开看：

| 歌 | 英文 token | 英文 exact | 中文 exact |
|---|---:|---:|---:|
| 孙燕姿 - 梦不落 | 16 | **50.0%** | 96.3% |
| 潘玮柏/张韶涵 - 快乐崇拜 | 34 | 94.1% | 90.6% |
| 元若蓝 - 爱x无限大 | 13 | 100% | 99.8% |
| 李晓杰 - 朋友的酒 | 5 | 40.0% | 98.0% |

合计英文 **53/68 = 78%**。不是「英文都不行」，是**多音节长词**那几句会崩。

**本轮做了**：英文词没有 `parts` 时，用「这个音数 == 音节粗估」判断「一个音一个音节」，
成立就把延音写 `+`（everywhere 3 音 3 音节 → `+ +`）；说不清（hello 2 音节占 3 音）
保守写 `-`。效果：**英文样本 Regression 的 marker 28.7% → 50.6%**，
混唱 marker 小幅上升，中文 exact 92.7% 不变。

**试过但没采用**：按音节「预留音数」（everywhere 预留 2 个音）+ 对英文词的距离降权。
《梦不落》的英文 token 从 50% 掉到 25~40%——因为 TIFA 给英文词的窗口只有一个音长
（everywhere 的 note 只有 0.12s，实际占 3 个音），音节粗估又不准，预留方向就是错的。

**`parts` 为什么是 0（2026-11-20 查清：源码问题，不是权重）**：
1. TIFA 后端本来就是双语加载的（`tifa_align.py:240`，`language=[zh, en]`，注释写明
   「拉丁词由它认领，汉字照走拼音」），所以混唱切片的 `phones` 层里英文词是 ARPAbet；
2. `parts` 是**我们自己**从 phones 层算的（`syllable_onsets`，最大开头原则的简化版），
   不是模型输出；
3. 旧代码只在 `self.language == "en"`（整首英文）时才调用它——混唱整首按中文跑，
   英文词的音节边界就被丢掉了。
→ 已改成 `word_syllable_onsets()`：整首英文照旧；中文歌里的拉丁词也切；汉字/假名不切
（拼音 `ao`/`en`/`er` 与 ARPAbet 撞名，只能按词面判断），`tests/test_asr.py` 覆盖。

**梦不落实测（2026-11-20）**：英文词的 phones 是 ARPAbet，但**标签带语言前缀**
（`en/eh` `en/v` `en/r` `en/iy`…），旧代码拿裸标签比 `_VOWELS` 永远匹配不上——
所以就算放开 gate，`parts` 也还是空。修了第二处（`_phone_name` 剥前缀）之后：
`everywhere → (0.28, 0.47)`（3 音节 2 个起点）、`people → (2.47,)`、单音节词为空。
整首重跑（407 字 / 33 个英文 token）里 4 个词拿到 parts；marker 21→22（+1），exact 不变。
只 +1 的原因：英文词仍只占一个音（字级 DP），parts 指向的第二/三音节所在的音被下一个词
占了，没有位置写 `+`。

另外修了一个评测侧 bug：`bench._shifted()` 平移 offset 时把 `parts` 丢了，
不修就永远测不出 parts 的作用。

**分段派发（2026-11-20 已做）**：`lyrics._refine_latin_runs()` —— 连续的英文段在
「相邻中文头之间」的音符区间里交给 `_align_latin_words` 重排，中文头一个都不碰。
门槛：**只有带 `parts` 的英文段才重排**（没有音节信息时词级 DP 会把每个词当单音节，
反而更差：《梦不落》英文 token 50% → 27%）。

《梦不落》实测（同一份重跑歌词，只切有/无派发）：

| 口径 | 旧 lyrics（无 parts） | 重跑 + parts，不派发 | 重跑 + parts + 派发 |
|---|---:|---:|---:|
| 英文 token exact | 50%（8/16） | 42%（7/17） | **53%（9/17）** |
| 整首 exact | 86.8% | 84.3% | 84.6% |
| marker | 23/33 | 21/33 | 22/33 |

`everywhere` 现在能写成 `everywhere + -`（人工是 `+ +`）；最后一处 `+` 仍差，
因为 `we` 自己的字时间偏了，`_align_latin_words` 的词头上界被它的开始时间卡住。

《快乐崇拜》重跑（含 parts + 派发）效果明显得多：

| 口径 | 旧 lyrics | 重跑 + parts |
|---|---:|---:|
| 整首 exact | 86.0% | **91.7%** |
| marker | 7/21（33.3%） | **17/21（81.0%）** |
| 英文 token exact | 32/34（94%） | 29/32（91%） |

marker 从 33% 跳到 81%：`old school / show yall / ready` 这类词的 `+` 段现在按音节写对了。
说明这条链路的价值主要在 **`+`/`-` 标记**，词头精度还受词时间限制。

《爱x无限大》没有音频，还没重跑。

**剩下的一步**：现有 19 首混唱的 `lyrics.json` 是旧版本产出的（`parts` 全 0），
要**重跑歌词阶段**（需要音频）才会带上 `parts`；带上之后上表的 53% 才会进基准。

**数据门槛**：混唱这个 slice **5~8 首**（最好带 `parts`）就能验收；
纯英文歌 15~30 首是另一件事（英文 ≥95% 的证书），不是修混唱的前提。

## 3. 两个判据要改

### 3.1 快嘴/rap 用「字密度」，不是「字/音」

`docs/对齐器-数据规模与语言矩阵调研.md` §3.4 原来写「快嘴 = 字/音 > 1.3」，这条是错的：
《快乐崇拜》692 字 / 711 音 = **0.97**，按它会被判成「不密」，但它是 rap。
字/音 衡量的是「字多还是音多」，rap 的特征是**单位时间吐多少字**。

按字密度重排：

| 歌 | 字/秒 | 10s 峰值字数 | ≥3 字/秒窗口占比 | 备注 |
|---|---:|---:|---:|---|
| 天真的橡皮 | 3.71 | 45 | 92% | 整首都快 |
| **快乐崇拜** | **3.37** | **67** | 68% | rap + 对唱 + 中英混唱 |
| 小炎 - 天下的乌鸦一般黑 | 2.85 | 41 | 77% | 快段被 1 音偏移污染 |
| 爱x无限大 | 2.56 | 49 | 41% | |
| 问天 | 2.39 | 39 | 45% | |
| 灯火里的中国 | 1.27 | 21 | 0% | 合唱 |

「密集吐字更难」有数据，但不是密度本身造成的：全库快段 exact 68.9% vs 非快 83.4%，
剔掉小炎（快段 5.6% 是 1 音整体偏移）后快段 81.7% ≈ 非快 84.5%；
单看《快乐崇拜》同一首歌：慢段 95.9% vs 快段 66.7%，那 29pp 里有相当部分是
**英文词没有 `parts`、走中文贪心**造成的。

所以 rap 缺的不是「再加 8 首普通快歌」，而是 **3~5 首干净的中文 rap**（纯中文、无英文、
音符干净、manual 无全局偏移），用来单独归因。

### 3.2 拍号 / 变速不进秒域评测集

挂字在**秒域**做：`bench.read_svp_notes()` 先按 SVP 自己的 tempo 表把 tick 换成秒，
`assign_lyrics()` 只吃 `(start, end)`。拍号与变速只影响 ① 音符层 → tick 与 tick ↔ 秒 的映射，
映射完就不可见。

- 6/8、2/4、3/4、变速 **不需要靠收样本覆盖**，留在 `scripts/verify.py` 的集成验证里
  （相思 6/8、巴拉莱卡 2/4、皮囊 变速已经在了）；
- 要防的是「量化后 tick 变了、字时间对不上」——那是 `raw_tick`/`raw_dur` 的契约，
  由 `scripts/check_pipeline_contract.py` 锁。

> 这条推翻了上一轮清单里「6/8、2/4、变速各补 3~5 首」的建议。

## 4. 分层口径（`bench.py` 已实现）

`scripts/bench_score.py` 默认把两类样本**拿出主指标、单列**：

| 桶 | 判据 | 理由 |
|---|---|---|
| `stress` | `meta.json` 的 `split == "stress"` | 音符层就选了另一条旋律：《灯火里的中国》自动 356 音 / 人工 330 音；挂字算法再准也挂不到一条不存在的旋律上 |
| 文本不一致 | `text_similarity < 0.7` | 人工词与 `lyrics.json` 整句不同（巴拉莱卡 51.9%、皮囊 55.2%），content/marker 量的是文本差异 |

0.7~0.9 之间（元若蓝 87.8%、蒋大为 89.8%）**仍进主指标**：文本差异只压低几分，
但会打告警。`--include-stress` 才把 stress 并回主指标（文本 <70% 的始终单列）。

## 5. 补什么（按失败模式，不按曲风）

| 失败模式 | 现状 | 补多少 | 从哪来 |
|---|---|---:|---|
| 文本一致 + ASR 时间戳 | 3 首可用（最炫/相思/光芒） | **10~15 首** | 巴拉莱卡/皮囊 用同一份文本重跑对齐即可转正 |
| 字多音少（字/音 > 1.3） | 1 首（待修） | 3~5 首 | 巴拉莱卡转正 |
| 多音节词 / `parts` | **0** | 5~8 首 | 中英混唱（必须带 `parts`），DLC 等英文暂不做 |
| 干净的中文 rap | 0 首可归因 | 3~5 首 | 新收：纯中文、无英文、音符干净 |
| 粤语（同分支，OOV/繁简/ASR 文本） | 0 对 | 20~30 首 | 富士山下（缺 lyrics，要重跑）等 |
| 对唱 / 合唱 | 2 首 | **不补数量** | 只补 `split=stress` 标注 |
| 拍号 / 变速 | — | **不需要** | 见 §3.2 |

结构上更便宜的几件事：

1. `meta.json` 的 `genre` / `difficulty` / `split` 补全，按**歌手**切 dev/test；
2. `bench_score.py` 补 cluster bootstrap（歌级均值已加）；
3. offset 改成分段搜索；
4. 补「人工/自动音符序列对齐 + product 模式」（端到端口径）。
