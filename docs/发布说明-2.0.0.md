# SheetSage2 Studio 发布说明 · 2.0.0

> 发布日期：2026-11-25　｜　上一版：`v2.0-beta3`（本版共 39 个提交）　｜　面向用户的变更都在这里；内部重构单独一节，不影响使用方式。

## 一句话

**批量**从"一首一首拖"变成"一个文件夹跑一整晚"：扫描/拖文件夹、串行排队、失败跳过、暂停、继续剩余、整批下载。外加 **A 卡（AMD ROCm）实验支持**。

---

## 1. 批量导入（全新）

| 能力 | 说明 |
|---|---|
| 两种入口 | ① 填/选文件夹路径（服务端扫描，**零上传**）；② 直接把文件夹**拖进页面**（逐个上传，可断点续传） |
| 歌词自动配对 | 同名 `.lrc`/`.txt` 自动带上；四态标记（LRC / LRC·日 / LRC·韩 / 无词） |
| 单批上限 | **100 首**；超了在扫描阶段就拦，不会建出"半批" |
| 批次命名 | `文件夹名 · 月-日 时:分`（同分钟重名追加 `(2)`），不再有"拖入的 N 首" |
| 串行队列 | 一首跑完自动接下一首；**不并行**（串行是当前设计，见调研文档） |
| 批次视图 | 进度 = 完成首数/总数（不是加权百分比）；点任意一行 = 打开原来的工程页 |
| 打包下载 | 一次导出整批 SVP（每首一个 `.svp` + `_manifest.json` 清单，同名自动 `-2`） |
| 整批删除 | 二次确认；批次还在跑/排队时先点「停止」再删 |

## 2. 批量健壮性

- **失败跳过**：某首扒谱失败，它的歌词阶段标 `skipped`，不会白跑一遍、也不会拿旧谱面填新歌词。
- **磁盘满自动暂停**：不再"40 首连着失败 40 次"；清出空间后点「继续剩余」。
- **继续剩余 N 首**：崩溃/断电/手动停止之后，一次把没跑完的成员重新排队，已完成的绝不重跑。
- **上传续传**：拖文件夹传一半断了，重拖同一个文件夹会接着传；批次页显示「还差 N 首」。
- **暂停语义**：暂停只停止派发，正在跑的那一首不打断。

## 3. 歌词与对齐

- 粤语默认走中文 G2P；**日/韩 LRC 改走 Qwen 强制对齐器**。
- 韩语不再静默落回中文。
- 延音窗口延伸到下一个字的起点（粤语 marker 命中 45% → 84%，中文 82.7% → 86.1%）。
- 拆音节时去掉空白字符；Qwen 对齐器的 CJK/韩语词级时间戳按音节拆开。
- `read_lrc` 剥掉行内说话人前缀（`[00:12] 歌手：` 这类）。
- LRC + TIFA 路径**不再加载 6.3 GB 识别模型**：40 首批量能省掉 40 次加载/卸载。

## 4. 启动与分发

- 不再用 `explorer.exe` 开浏览器（部分机器 `0xc0000142`）；带 `unblock_files.bat` 与 FAQ。
- 等端口真就绪再开浏览器，避免"Failed to fetch"。
- 单实例锁、看门狗、回收站、备份/迁移等沿用 beta 的机制。

## 5. AMD ROCm（实验特性，需手动开启）

> **NVIDIA 用户不受任何影响**：默认仍用 `.venv`（CUDA），下面这一节可以跳过。

- 入口：包根新增 **`03_AMD_ROCm.bat`**（等价于 `01_install.bat rocm`）。
- 它做的事：复制 `.venv` → `.venv-rocm`（原环境不动），只把 torch/torchaudio 换成 **`torch 2.9.1+rocm7.2.1`**（AMD 官方轮子，约 1.8 GB，可断点续传），然后写 `.env-backend`。
- 启动器按 `.env-backend` 挑解释器；启动横幅会多一行「GPU 后端：AMD ROCm（卡名，hip=x.y）」。
- 预检横幅、诊断包、`scripts/verify.py` 都会带上 `hip` 版本，方便排查。
- bf16 不被支持时（RDNA2 一类）自动落 fp16；HIP/MIOpen 的错误会归到「显存不足/设备不可用」。
- **支持范围以 AMD 官方为准**：Windows 只有 RX 9000 系与"select 7000 系"（gfx12xx / gfx11xx）。**RX 6000 系（RDNA2，含 6750 GRE）不在列表里**，这套方案在那些卡上大概率跑不起来。
- 卸载/回退：删 `.venv-rocm\` 和 `.env-backend` 即回到 N 卡环境。

## 6. 内部：模块化重构（使用方式不变）

- `app.py` 拆成 `routes/` 包；`jobs.py` 拆成 `job_models / job_options / job_files / job_errors / job_storage / job_trash / job_backup / job_scheduler`，`jobs.py` 只留门面。
- 前端 `useStudio` 拆成 `useJobs / useJobEvents / useUploads / useTrashBackup`；`styles.css` 按职责拆分。
- 好处：以后修一个阶段/一个接口不用再在 3000 行文件里找；issue 定位快。

## 升级须知

1. **版本号统一为 `2.0.0`**（`pyproject.toml`、`downloads.json`、`/api/env.version` 三处此前不一致）。
2. 工程目录结构**没有变化**：`output/<歌名>/.webui/job.json` 兼容 beta3，直接覆盖安装即可。
3. 旧批次的名字**不会自动改**：beta 阶段建的"拖入的 N 首"还叫原名，新建的才是新格式。
4. `job.json` 会带 `batch` 字段（含 LRC 文本）；40 首左右的全量列表约 0.5 MB——批量视图用的是轻量接口（`/api/jobs?view=rows`），不影响侧栏轮询。

## 已知问题

- **AMD ROCm 尚无真机验收**：代码路径与安装链路已就绪，但还没有一台 A 卡机器跑通并回传结果；标"实验"，不建议直接给不折腾的用户。
- 批量**不并行**（P2 冻结，调研文档里有方案）。
- 拖文件夹的"续传"逻辑有单测，但真实文件夹拖拽只能人工验一次。
- 批量页的"继续剩余"按 index 重排；批次内顺序依赖扫描/上传顺序，手工改过 `job.json` 的批次除外。
