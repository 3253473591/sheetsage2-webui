## 问题与建议

### P2：终态 SSE 续传分支异常，属于拆分前已有问题

位置：`src/sheetsage2_webui/webui/routes/_shared.py:62`。

任务已结束，客户端用 `since=最后事件序号` 重连 `/api/jobs/{id}/events` 时，会进入补发终态事件分支。`terminal_event()` 读取 `job.error`，但 `Job` 没有此属性。独立 TestClient 复现得到 `AttributeError: 'Job' object has no attribute 'error'`，导致流异常结束。

基线 `app.py` 的 `_terminal_event()` 有相同读取，因此不能归因于拆分。建议从阶段错误或 `snapshot()` 取得错误，并补“终态且没有待补事件”的路由回归测试。

### 遗留的前端轮询缺口

位置：`web/src/composables/useStudio.ts:165`、`:178`。

`runStage()` / `runChain()` 成功后只补开 SSE，没有启动兜底轮询。已完成工程的旧轮询已停止，重跑后遇到 SSE 静默失效可能停在旧进度。基线也存在这一调用方式，属于旧缺口。建议使用启动 SSE 与轮询的统一入口，并补完成工程重跑的集成测试；现有事件测试主要覆盖事件补丁，没有覆盖这条编排路径。

### 旧 Python 导入路径兼容性

`webui.runner.pick_asr_model` 移到了 `runner_models`，当前从旧路径导入会失败。实施记录已说明这个取舍，仓内使用不受影响；但该名称没有下划线，不能直接假定所有外部调用都不存在。若需要保持旧脚本兼容，建议在旧模块保留薄转发，并验证旧导入路径。

只有 `asr.py` 略超千行，已有算法内聚性例外说明，符合计划“尽量”的口径；不能表述为所有文件严格小于 1000 行。结构文档中的 `jobs.py ~678`、`tempo.py ~857` 与物理行数不符，建议统一统计口径。

拆分采用真实职责边界，领域对象与选项成为底层模块，存储不管理队列，调度通过查找回调取得任务，路由通过依赖对象组装；前端的作业列表、事件流、上传和回收站各有明确入口。整体内聚性与耦合度较基线改善。

`jobs.py` 仍保留较多工程级策略；存储恢复中仍通过局部导入调用 runner 的展示摘要函数。属于可维护的剩余依赖，后续应按实际变化原因收敛，不宜为了继续减行数机械拆分。
